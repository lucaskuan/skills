# Writing a docs page

Every promoted skill has a page at `docs/<bucket>/<skill-name>.md`. Four sections, in this order.

## What it does

Two or three sentences. What the skill actually performs, in the reader's terms, not the implementation's. Name the systems it touches.

## When to reach for it

The situation, not the trigger phrase. A reader who has the problem should recognise it here. Say what it is *not* for if there is a nearby skill that people confuse it with.

## Common questions

Real questions, harvested from what actually went wrong. Sources: mistakes made while using the skill, questions asked in the session that produced it, and the failure modes its SKILL.md warns about. Do not invent questions nobody asked.

## It's working if

Concrete, observable outcomes. The reader should be able to check each one. "You get a chart" is weak. "The per-charger stacked panel sums to the cluster Import line at every bucket" is checkable.
